## 3. Желаемое имя репозитория и жёсткое ограничение

**Намерение:** описательное имя `kinetic-visuals-premium-reference-study-2`.

Это **намерение, а не гарантированный результат**. Ограничения Git Sync:

- Подключение **всегда создаёт новый приватный репозиторий**; связать или импортировать уже существующий репозиторий нельзя.
- Поля выбора имени репозитория при подключении документация не описывает — имя задаёт Lovable.
- Поведение при занятом имени (например, если `kinetic-visuals-premium-reference-study-2` уже существует) документацией не определено: результат может отличаться от ожидаемого; при неожиданном итоге — карточка статуса в Project settings → Git или обращение в поддержку Lovable.
- После подключения репозиторий можно переименовать в GitHub — синхронизация продолжается автоматически. Это и есть практичный путь получить именно это имя.
- Отключённый репозиторий нельзя перезалить обратно: повторное подключение создаёт ещё один новый репозиторий. Удаление репозитория останавливает синхронизацию.

**Практический вывод:** имя `kinetic-visuals-premium-reference-study-2` получается переименованием уже созданного репозитория в GitHub после подключения, а не созданием репозитория вручную заранее.

## 4. Шаги подключения (выполняет владелец, только в интерфейсе Lovable)

1. Открыть проект в редакторе Lovable.
2. Project settings → Git → GitHub → Add account / Install & Authorize; по возможности выбрать только нужный GitHub-аккаунт и наименее широкий доступ (least privilege).
3. Connect. Lovable создаёт новый приватный репозиторий и включает двустороннюю синхронизацию.
4. Проверить карточку статуса: «In sync», какая сторона впереди или есть расхождение; активная ветка — по умолчанию `main`.
5. При необходимости переименовать репозиторий в GitHub в `kinetic-visuals-premium-reference-study-2` (пункт 3 раздела 3).

Роли: подключение и отключение — owner или admin (workspace/project); просмотр статуса и переключение ветки — editor и выше. Доступ на запись в репозиторий на стороне GitHub — отдельное требование.

## 5. Чего не делать

- Не создавать репозиторий вручную «чтобы потом подключить» — связать его нельзя.
- Не менять remote и не выполнять ручной `git push`/`pull`/переписывание истории: коммиты делает платформа, синхронизацию выполняет Lovable.
- Не удалять репозиторий после подключения.
- Не переносить исходники в новый Lovable project ради репозитория.
- Публикацию и домен этот шаг не касается: сайт остаётся неопубликованным, DNS не меняется.
